# Manga AutoExtract — افزونهٔ کروم

افزونهٔ کروم مستقل برای استخراج عکس مانگا و مانها از هر سایت.
کاملاً جدا از کد اصلی پروژه (شاخهٔ `chrome`) و بدون هیچ کامنتی در کدها.

نسخه: 1.1.6

## قابلیت‌ها

- کلید روشن/خاموش در پاپ‌آپ فقط افزونه را فعال/غیرفعال می‌کند — خودکار ضبط نمی‌کند؛ دکمهٔ «ضبط» پایین صفحه ظاهر می‌شود
- با زدن دکمهٔ «ضبط»: صفحه یک بار بازخوانی و ضبط شروع می‌شود و دکمه به «استخراج» تغییر می‌کند
- «متوقف ضبط» فقط ضبط را متوقف می‌کند — افزونه روشن می‌ماند و دکمهٔ «ضبط» برمی‌گردد
- ضبط سراسری: با عوض کردن فصل، سایت یا حتی تب، ضبط ادامه می‌یابد و عکس‌های قبلی حفظ می‌شوند — فقط با «متوقف ضبط» پاک می‌شوند
- انتخاب تکی عکس‌ها (مثل مرورگر داخلی اپ): تیک هر عکس، تیک هر پوشه، دکمه‌های «همه» و «هیچ» — فقط عکس‌های انتخاب‌شده کپی یا دانلود می‌شوند
- استخراج با لینک: لینک‌های عکس‌های انتخاب‌شده با دکمهٔ «کپی لینک‌ها»، کپی هر پوشه و حالت متنی برای کپی دستی کامل
- استخراج با دانلود: عکس‌های انتخاب‌شده دانلود و در یک فایل ZIP جمع می‌شوند
- ترتیب عکس‌ها از سند HTML صفحه (مثل نسخهٔ فعلی) و ذخیره به همان ترتیب: `1.jpg`، `2.jpg`، `3.jpg` و...
- فیلتر خودکار عکس‌های کوچک، لوگو، آیکون، SVG و تبلیغات
- گروه‌بندی لینک‌ها بر اساس پوشهٔ URL
- بندانگشتی هر عکس + کلیک روی هر ردیف برای دیدن عکس کامل
- پشتیبانی از عکس‌های blob درون صفحه (مثل مانگاپلاس) و لینک‌های پروکسی (مثل `img-proxy?url=...` مانگاریدر)
- رابط فارسی و راست‌به‌چپ
- کار روی همهٔ پلتفرم‌ها: ویندوز، لینوکس، مک و اندروید

## ساختار فایل‌ها

| فایل | نقش |
|---|---|
| `manifest.json` | تعریف افزونه (Manifest V3) |
| `background.js` | سرویس‌ورکر: ضبط لایهٔ شبکه با webRequest، دانلود فایل با chrome.downloads |
| `content.js` | رابط کاربری روی صفحه: دکمهٔ ضبط، منو، پنل لینک‌ها، ساخت و ذخیرهٔ ZIP |
| `page-hook.js` | قلاب درون صفحه: گرفتن عکس‌های blob (مانگاپلاس) و fetch |
| `inject.js` | تزریق page-hook در دنیای اصلی صفحه |
| `zip.js` | سازندهٔ فایل ZIP (بدون کتابخانهٔ خارجی) |
| `popup.html` و `popup.js` | پاپ‌آپ آیکون: کلید خاموش/روشن ضبط + راهنما |
| `icons/` | آیکون‌های 16 و 48 و 128 (قرمز، همسان با آیکون اپ) |

## نصب روی ویندوز و لینوکس و مک

مرورگر: کروم، اج، بریو، اپرا یا هر کرومیمی دیگر

1. فایل ZIP رلیز را دانلود و extract کن
2. در آدرس‌بار بنویس: `chrome://extensions`
3. بالای صفحه «حالت توسعه‌دهنده» (Developer mode) را روشن کن
4. روی «بارگذاری بدون بسته‌بندی» (Load unpacked) کلیک کن و پوشهٔ extract شده را انتخاب کن
5. افزونه نصب شد — برو داخل سایت مانگا

## نصب روی اندروید

مرورگر رسمی کروم روی اندروید افزونه ندارد. از Kiwi Browser استفاده کن (از کرومیوم ساخته شده و افزونهٔ کروم را ساپورت می‌کند):

1. Kiwi Browser را نصب کن (از فروشچه Play یا سایتش)
2. فایل ZIP رلیز را دانلود و با فایل‌منیجر extract کن (مثلاً در `Download/manga-chrome`)
3. در Kiwi آدرس‌بار بنویس: `chrome://extensions`
4. حالت توسعه‌دهنده را روشن کن
5. روی «Load unpacked» بزن و پوشهٔ extract شده را از حافظهٔ گوشی انتخاب کن

## روش استفاده

1. کلید پاپ‌آپ افزونه را روشن کن — دکمهٔ «ضبط» پایین صفحه ظاهر می‌شود (ضبط هنوز شروع نشده)
2. فصل مانگا را باز کن و دکمهٔ «ضبط» را بزن — صفحه یک بار refresh می‌شود و ضبط شروع می‌شود
3. فصل را اسکرول کن تا همهٔ صفحات لود شوند (عکس‌های lazy هم دیده می‌شوند)
4. دکمهٔ «استخراج» را بزن — پنل لینک‌ها روی همان صفحه باز می‌شود
5. عکس‌های دلخواه را تیک بزن و بعد انتخاب کن:
   - «کپی لینک‌ها»: لینک‌های انتخاب‌شده کپی می‌شوند (کپی هر پوشه و حالت متنی هم هست)
   - «دانلود ZIP»: عکس‌های انتخاب‌شده یکی‌یکی دانلود می‌شوند، ZIP ساخته می‌شود و ذخیره می‌شود
6. بعد از پایان، مسیر و نام فایل ZIP نمایش داده می‌شود و قابل کپی است
7. اگر لینکی دانلود نشود، تعداد و دلیلش نمایش داده می‌شود و دکمهٔ «کپی لینک‌های ناموفق» هست

## ترتیب و شماره‌گذاری

- ترتیب عکس‌ها همان ترتیب نمایش در سند HTML صفحه است (مثل نسخهٔ فعلی برنامه)
- داخل ZIP عکس‌ها به همان ترتیب شماره می‌خورند: `1.webp`، `2.webp`، ... (پسوند واقعی هر عکس حفظ می‌شود؛ اگر پیدا نشود `jpg` می‌شود)
- عکس‌های تکراری (blob و لینک اصلی یک عکس) خودکار حذف می‌شوند

## محل ذخیرهٔ فایل ZIP

- ویندوز و لینوکس: زیرپوشهٔ `MangaAuto` داخل پوشهٔ دانلود مرورگر — مثال: `C:\Users\<نام>\Downloads\MangaAuto\manga_mangareader_115_20img.zip`
- اندروید: پوشهٔ Download گوشی — مثال: `/storage/emulated/0/Download/manga_mangareader_115_20img.zip`

نکته: کروم به دلایل امنیتی اجازه نمی‌دهد افزونه در جای دلخواه دیسک بنویسد — محل ذخیره همان پوشهٔ دانلود مرورگر است و مسیر دقیق بعد از ذخیره روی صفحه نمایش داده می‌شود.

## روش بسته‌بندی برای توزیع

روی ویندوز: روی پوشه راست‌کلیک و Send to / Compressed (zipped) folder

روی لینوکس و مک:

```bash
cd manga-chrome
zip -r ../MangaAutoExtract-v1.1.1.zip .
```

فایل ZIP آماده توزیع است — کاربر آن را extract می‌کند و با «Load unpacked» نصب می‌کند.

## روش ساخت نسخهٔ جدید (توسعه)

پیش‌نیاز: هیچ — افزونه هیچ کتابخانهٔ خارجی و هیچ build ندارد؛ فایل‌ها همان‌طور که هستند اجرا می‌شوند.

1. فایل مورد نظر را ویرایش کن (مثلاً `content.js`)
2. در `chrome://extensions` روی آیکون refresh افزونه بزن
3. صفحه سایت را refresh کن و تست کن
4. شمارهٔ `version` در `manifest.json` را بالا ببر (مثلا `1.1.2`)
5. commit کن و پوش کن:

```bash
git add -A
git commit -m "v1.1.2"
git push
```

6. برای رلیز: tag بزن و ZIP را به رلیز GitHub اضافه کن

قواعد کدگذاری این شاخه:

- هیچ کامنتی در کدها نیست و نباید اضافه شود (`#` و `"""` و `/* */` و `//`)
- همهٔ متن‌های رابط فارسی هستند
- زبان‌ها: جاوااسکریپت خالص (ES2020) و JSON

## نحوهٔ کار (معماری)

سه لایهٔ جمع‌آوری همزمان:

1. لایهٔ شبکه: `background.js` با `chrome.webRequest.onResponseStarted` همهٔ پاسخ‌های `image/*` را می‌بیند — دقیقاً همان چیزی که در پنل Sources/Network کروم دیده می‌شود؛ حتی عکس‌های داخل Service Worker سایت و عکس‌های پروکسی مثل `img-proxy?url=...` (مثل مانگاریدر) — URL داخل پارامتر url خودکار decode می‌شود
2. لایهٔ HTML: `content.js` یک گذر روی سند صفحه می‌زند به ترتیبِ نمایش (img و source و srcset و data-src و...)
3. لایهٔ blob: `page-hook.js` در دنیای اصلی صفحه `URL.createObjectURL` را قلاب می‌کند و عکس‌های رمزگشایی‌شدهٔ درون صفحه (مثل مانگاپلاس) را نگه می‌دارد

نتیجهٔ سه لایه merge و dedupe می‌شود (ترتیب: HTML اول، بعد شبکه، بعد blob) و بعد فیلتر زباله اعمال می‌شود.

دانلود عکس‌ها: اول از سرویس‌ورکر (بدون محدودیت CORS، با Referer صفحه از طریق قانون declarativeNetRequest)، اگر نشد از خود صفحه (با Referer و کوکی خود صفحه — مناسب سایت‌هایی مثل وب‌تونز که بدون Referer خطای ۴۰۳ می‌دهند) — محتوای دریافت‌شده با بایت‌های جادویی (magic bytes) اعتبارسنجی می‌شود و فایل خراب یا HTML خطا به‌جای عکس ذخیره نمی‌شود؛ سپس ZIP با متد STORE ساخته و با `chrome.downloads` ذخیره می‌شود (روی اندروید در صورت نبود API، دانلود معمولی مرورگر).

## محدودیت‌ها

- محل ذخیره فقط پوشهٔ دانلود مرورگر است (قانون کروم)
- روی اندروید فقط مرورگرهای کرومیِ با پشتیبانی افزونه (مثل Kiwi) کار می‌کند
- عکس‌هایی که سایت با لینک موقت یک‌بارمصرف می‌دهد ممکن است بعد از بستن صفحه دیگر باز نشوند — همان موقع دانلود کن
- فایل‌های ZIP حجیم (بیش از چند صد مگابایت) ممکن است روی گوشی‌های کم‌رم کند باشد
